# spec 작성 규약

설계 문서는 **결정을 남기는 문서**다. 무엇을 만들지가 아니라 **왜 이렇게 만들기로 했고 무엇을 포기했는지**를 남긴다. 구현 방법만 적힌 문서는 6개월 뒤 근거 없이 뒤집힌다.

경로: `docs/superpowers/specs/{YYYY-MM-DD}-{slug}-design.md`
전체 골격은 `references/spec-template.md`에 있다. 처음 쓸 때는 반드시 읽는다.

## 필수 절

| 절 | 없으면 생기는 일 |
|---|---|
| **목적** | 무엇을 해결하는지 합의 없이 구현이 시작된다 |
| **결정 사항** (표) | 구현자가 매 갈림길에서 임의로 정한다 |
| **아키텍처** (다이어그램) | 데이터가 어디서 어디로 가는지 사람마다 다르게 이해한다 |
| **스키마 / 인터페이스** | 태스크 간 경계가 정의되지 않아 계획을 못 쪼갠다 |
| **에러 처리** (표) | 실패 분류가 코드마다 달라진다 — 이 저장소에서 **반복적으로 버그가 된 지점** |
| **검증 계획** | "다 됐다"의 기준이 없다 |
| **알아둘 트레이드오프** | 대가를 나중에 결함으로 오인한다 |
| **범위 밖 (YAGNI)** | 구현이 무한히 번진다 |

선행 문서의 결정을 뒤집을 때는 **"선행 문서로부터의 변경"** 절을 추가하고, 그 문서가 든 근거를 하나씩 재평가한다.

## 결정표 쓰는 법

```markdown
| 항목 | 선택 |
|------|------|
| 결합 방식 | **건당 인라인 체인** (한 커맨드, 한 루프) |
| 커밋 순서 | `markDetailDone` → `markStructureDone` → `markEmbedDone`, **각각 즉시 커밋** |
| 동시성 | **없음 (순차 고정).** 속도가 요구사항이 아니다 |
```

표는 결론만 담는다. **근거는 본문 산문에서 전개한다.** 표에 근거까지 밀어 넣으면 둘 다 읽히지 않는다.

## 에러 처리 표 쓰는 법

축은 최소 네 개다. 실패 지점을 빠짐없이 세로로 나열한다 — 외부 API, LLM, DB, 파싱, 검증 각각.

```markdown
| 실패 지점 | 상태 변경 | attempt | 루프 |
|---|---|---|---|
| **TourAPI 한도초과** | **변경 없음** | **미증가** | **즉시 중단** |
| TourAPI `NODATA(03)` | `detail_status='nodata'` | 미증가 | 계속, 체인 미진입 |
| **DB 쓰기 실패** | 변경 없음 | 미증가 | **예외 전파 → 중단** |
```

**핵심 판단 기준: 이 실패의 책임이 누구에게 있는가.**
- 데이터의 문제 → 그 항목의 시도 횟수를 올린다
- 호출자 사정(쿼터 소진·인증 만료) → **시도 횟수를 올리지 않는다.** 올리면 멀쩡한 데이터가 매일 실패를 쌓아 영구 제외된다
- 우리 쪽 저장 실패 → 삼키지 않고 전파한다. 삼키면 이미 지불한 비용을 버리면서 남의 attempt를 올린다

## 근거를 쓰는 법

**나쁨:** "성능을 위해 인라인으로 처리한다."
**좋음:** "선행 문서의 분리 근거는 '한 트랜잭션이면 Qdrant 다운이 이미 소비한 API 호출을 날린다'였다. 전제가 '한 트랜잭션'이다. `markDetailDone`을 먼저 커밋하면 그 시점에 TourAPI 호출은 영구 보존되고, 이후 어떤 실패도 복구 가능해진다. 근거는 커밋 경계 설계로 무력화된다."

차이는 **반박 가능성**이다. 좋은 근거는 어디를 공격해야 뒤집히는지 보여준다.

## 현행을 특정하는 법

변경을 제안하기 전에 현행을 파일·줄 번호로 인용한다.

> 현행 `QdrantStore`에는 컬렉션의 존재 여부나 벡터 차원을 읽는 메서드가 없다(`clients/qdrant.ts` — `createCollection`/`deleteCollection`/`upsert`/`search`/`deletePoints`만 있음).

인용 없이 "현재 구조가 부족하다"고 쓰면, 구현 단계에서 실제 코드와 어긋나 계획 전체가 무너진다.

## 하지 말 것

- **코드를 쓰지 않는다.** 인터페이스 시그니처와 SQL DDL은 예외 — 그건 계약이지 구현이 아니다.
- **"적절히", "필요에 따라", "상황에 맞게"** — 결정을 미루는 표현. 결정하거나, 미해결 질문으로 올린다.
- **모호한 요구사항을 임의로 확정하지 않는다.** 갈림길과 각 선택의 귀결을 미해결 질문에 담아 반환한다.
- **선행 문서를 지우지 않는다.** 뒤집더라도 비교표로 남긴다.

## 언어

문서 본문은 한국어. 코드 식별자·파일 경로·명령은 원문 그대로.
