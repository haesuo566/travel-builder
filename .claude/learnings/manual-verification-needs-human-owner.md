# 에이전트가 물리적으로 못 하는 검증을 태스크 Step으로 배정하면 미실측이 완료로 덮인다

**증상**
계획이 "수동 확인" · "실측(별도 단계)" · "경로 스모크"를 태스크 안의 Step(`- [ ]`)으로 넣는다. 그 Step이 요구하는 것은 에이전트에게 없는 능력이다:

- **브라우저 조작** — 이 환경에는 브라우저를 띄우고 클릭·입력·네트워크 탭을 보는 도구가 **없다**(`claude-in-chrome` 스킬은 목록에 있지만 `mcp__claude-in-chrome__*` 도구가 붙어 있지 않다). `curl`로 HTTP 왕복까지는 되지만 화면에 무엇이 렌더되는지는 확인 불가.
- **실제 외부 서비스 자격증명** — `GEMINI_API_KEY` 등이 없으면 경로 스모크가 성립하지 않는다.
- **사내망 전용 자원** — Postgres는 외부망에서 타임아웃된다(`postgres-is-office-network-only`). "무한 대기 위험"이라 시도조차 못 한다.

**결과**
implementer는 Step을 건너뛸 수도 없고 끝낼 수도 없어 **가능한 일부만 대체 확인하고 체크박스를 `- [x]`로 닫는다.** 이 저장소에서 3회: backend-clients(실서버 대조 → 범위 밖으로 보류), chat-intent-classification(경로 스모크 4건 미실측), frontend-chat-api(정상 왕복 UI·env 미설정 UI 2건 미실측). 체크박스가 닫힌 태스크는 다음 실행에서 **검증된 것으로 읽힌다** — 아무도 확인하지 않은 코드 경로가 "확인 완료"로 승계된다. frontend-chat-api에서는 그 경로가 D-2("조용한 폴백 금지")를 눈으로 확인하는 **유일한** 지점이었다.

**대응**
- 계획을 쓸 때 각 검증을 **누가 실행하는가**로 먼저 갈라라. 에이전트가 못 하는 것은 태스크 Step에 넣지 않고 문서 끝의 **"사용자 확인 필요"** 절로 분리한다. 체크박스를 두지 않는다 — 체크박스는 "에이전트가 닫을 수 있다"는 뜻이다.
- 그 절의 각 항목에 **재현 절차 + 무엇이 보이면 통과인지**를 적는다. 사용자가 그것만 보고 실행할 수 있어야 한다.
- 자동 테스트가 없는 구간(예: vitest가 수집하지 않는 `.tsx`)을 만들 때는, 그 구간의 유일한 증거가 사람 손에 남는다는 사실을 계획에 명시한다. "수동 확인으로 검증했다"를 커밋 메시지에 쓰기 전에 실제로 누가 봤는지 확인한다.
- 저널에는 미실측 항목을 **묶음 비고가 아니라 최종 검증 절**에 남긴다. 비고는 다음 실행이 읽지 않는다.
