# 여러 부팅 경로가 공유하는 setup 함수는 DI 컨테이너에서 값을 꺼내지 말고 인자로 받는다

**증상**
`configureApp(app)`처럼 운영 부팅(`main.ts`)과 테스트가 **함께 부르는** 전역 배선 함수에 새 설정값이 필요해진다. 손이 먼저 가는 쪽은 함수 안에서 `app.get(ConfigService)`로 꺼내는 것이다 — 시그니처가 안 변하니 호출부를 안 건드려도 된다.

**결과**
그 편의가 정확히 문제다. 이 저장소의 호출부 세 곳 중 `test/external-service.e2e-spec.ts`는 전역 배선만 태우려고 만든 **프로브 모듈**이라 `ConfigModule`을 import하지 않는다 — 컨테이너 조회가 부팅 단계에서 죽는다. 고치려면 프로브에 env 배선을 들이거나(테스트 목적 오염), 다른 spec의 인라인 `ENV` 객체에 키를 더해야 한다. 어느 쪽이든 **타입 검사가 짚어주지 않으므로 실행해봐야 알게 된다.**

**대응**
- 공유 setup 함수에 설정값이 필요하면 **인자로 받는다.** 시그니처를 바꾸면 `tsc`가 호출부를 전부 열거해준다(`TS2554: Expected 2 arguments, but got 1`) — 배선 누락을 런타임 실패에서 컴파일 실패로 옮기는 거래다.
- 컨테이너 조회는 **모든 호출 경로가 그 모듈을 확실히 import할 때만** 쓴다. 판단 전에 `grep -rn <함수명> --include=*.ts`로 호출부를 세고, 각 호출부의 테스트 모듈이 해당 프로바이더를 갖는지 표로 확인한다.
- 축소된 테스트 모듈(프로브)을 살리기 위해 프로덕션 코드 형태를 고르는 것은 타협이 아니다 — 프로브가 전역 배선을 태우는 유일한 수단이다.
