## Global Constraints

- 작업 디렉터리는 `backend/`. 모든 명령은 거기서 실행한다.
- 주석·로그 메시지·에러 메시지·커밋 메시지는 **한국어**로 쓴다.
- 테스트 파일은 소스 옆 `*.spec.ts` (jest `rootDir`가 `src`).
- 단위 테스트는 전부 모킹이다. **실제 네트워크·DB 호출을 하지 않는다.**
- 테스트: `npm test` / 타입 검사: `npx tsc --noEmit -p tsconfig.json` / 린트: `npx eslint src --max-warnings=0`
- **기준은 이 문서의 코드 블록이 아니라 커밋된 코드다.** 블록이 현재 파일과 다르면 이탈로 보고한다.

## 태스크 앞 Step 번호

준비 작업(mock 추가 등)이 필요하면 Step 1 **앞에** 넣고 전체 번호를 밀어 쓴다. 다섯 Step의 **순서**가 규약이지 번호가 규약은 아니다.

```
- [ ] **Step 1: 테스트 mock에 getCollection 추가**
- [ ] **Step 2: 실패하는 테스트 작성**
- [ ] **Step 3: 실패를 확인**
- [ ] **Step 4: 구현**
- [ ] **Step 5: 통과를 확인**
- [ ] **Step 6: 커밋**
```

## 커밋 메시지 규약

```
{type}(backend): {한국어 제목 — 무엇을}

{왜 이렇게 했는지. diff가 말하지 않는 것만.}
```

- `type`: `feat` `fix` `refactor` `test` `docs` `chore`
- 제목은 명령형·한국어. 본문은 **왜**만 쓴다 — 무엇을 했는지는 diff가 말한다.
- `core`·`frontend`를 함께 건드리는 변경은 **워크스페이스별로 커밋을 나눈다.** 한 커밋에 묶으면 어느 쪽 테스트가 무엇을 보장하는지 추적이 끊긴다.
