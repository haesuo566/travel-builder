# learnings — 누적 학습

`compounder`가 실행마다 쌓는 복리 자산. `plan-writer` · `implementer` · `reviewer`가 **작업 시작 전에 이 디렉터리 전체를 읽는다.**

**이전 하네스의 학습 20개는 `c90e45a "삭제"` 커밋에서 전량 삭제됐고, `42cbea3`이 새 하네스를 구성하면서 학습을 비운 채 시작했다.** 다만 그 20개 중 **승급까지 갔던 것들의 내용은 새 스킬 본문이 이어받았다** — typed-lint 제약·로컬 `.env` 가짜 통과·실패 귀속·계획 코드 블록 스냅샷·저널 대조 등이 `tb-code-review`·`tb-plan-writing`·`tb-harness`·`backend-constraints.md`에 살아 있다. 승급하지 못한 나머지는 사라졌다.

살아 있는 소스 주석이 삭제된 학습을 아직 이름으로 참조한다: `src/chat/query/structured-query.ts:51`의 `two-columns-one-state` (이 학습은 어느 스킬에도 흡수되지 않았다). `src/chat/query/query.structurer.ts:39`의 `failure-attribution`은 내용이 `tb-code-review` 정확성 축에 남아 있다.

## 이 디렉터리의 목적

같은 실수를 두 번 하지 않는 것. 이 하네스의 review는 실행 증명과 재검증을 포기한 경량 모드이므로, **리뷰가 놓친 것을 다음 실행이 미리 아는 것**이 품질 방어선의 큰 몫을 진다.

## 파일 포맷

`{kebab-slug}.md` 하나에 학습 하나.

```markdown
---
type: pitfall | convention | environment | process
first_seen: {YYYY-MM-DD}
occurrences: {n}
promoted_to: {승급한 파일 경로 또는 없음}
---

# {한 줄 제목 — 무엇을 조심해야 하는가}

**증상**
{어떤 코드·상황에서 나타나는가}

**결과**
{그대로 두면 실제로 무슨 일이 일어나는가}

**대응**
{다음에 이 상황을 만나면 무엇을 하는가}

**출처**
{커밋 해시 + 제목 / 리뷰 보고서 경로 / 날짜}
```

| type | 무엇 |
|---|---|
| `pitfall` | 밟으면 버그가 되는 함정 |
| `convention` | 이 저장소가 따르는 관례 (코드를 읽어도 이유를 알 수 없는 것만) |
| `environment` | 도구·런타임·하네스 실행 환경의 제약 |
| `process` | 워크플로 자체에서 배운 것 (묶음 크기, 순서, 승인 지점) |

## 읽는 쪽을 위한 주의

- **파일·함수·플래그를 언급한 학습은 그것이 아직 존재하는지 확인한 뒤 적용한다.** 학습은 쓰인 시점의 사실이다.
- 서로 반대되는 두 학습이 보이면 어느 쪽도 임의로 무시하지 않는다. 오케스트레이터에게 보고한다.

## 쓰는 쪽(compounder)을 위한 규약

전체 규약은 `.claude/skills/tb-compound/SKILL.md`에 있다. 요약:

- **일반화해서 쓴다.** 좁은 규칙은 다음 상황에 맞지 않아 읽히고도 적용되지 않는다.
- **왜를 남긴다.** 그 규칙이 없었을 때 실제로 무슨 일이 일어났는지가 판단 기준이 된다.
- **2회 규칙.** 같은 성질이 2회 이상 반복되면 학습에 머무르지 말고 스킬·에이전트 정의로 승급한다.
- **틀린 학습은 지운다.** 축적은 늘리기가 아니라 정확도 유지다. 틀린 학습은 없는 학습보다 나쁘다.
- **없으면 만들지 않는다.** "이번 실행에서 새로 배운 것 없음"은 정당한 결과다.
