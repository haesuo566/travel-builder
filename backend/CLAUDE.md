# backend

## 하네스: 개발 파이프라인

**목표:** 코드 변경의 깊이를 사용자가 고르게 하고, 전 파이프라인을 태운 실행에서 잡힌 것이 다음 실행의 규칙으로 남게 한다.

**트리거:** backend의 기능 추가·변경·리팩터링·버그 수정 요청이 오면 `tb-harness` 스킬을 사용하라. "빨리 고쳐줘", "간단한 거니까 그냥" 같이 빠른 처리를 원하는 요청도 이 스킬로 받는다 — **스킬 진입 직후 게이트 0이 두 경로(A: `plan → work → review → compound` 전체, B: 바로 구현)를 제시하고 사용자가 고른다.** 경로를 대신 골라주지 않는다. 후속 요청("다시 실행", "이어서", "리뷰만 다시", "계획만 수정", "학습 정리해줘")은 진행 중인 실행의 경로를 유지하며 게이트 0을 다시 띄우지 않는다. 단순 질문·조회·설명은 직접 응답해도 된다.
