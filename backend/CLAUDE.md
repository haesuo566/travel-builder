# backend

## 하네스: 개발 파이프라인

**목표:** 모든 코드 변경이 `plan → work → review → compound`를 통과하게 하고, 리뷰에서 잡힌 것이 다음 실행의 규칙으로 남게 한다.

**트리거:** backend의 기능 추가·변경·리팩터링·버그 수정 요청이 오면 `tb-harness` 스킬을 사용하라. 후속 요청("다시 실행", "이어서", "리뷰만 다시", "계획만 수정", "학습 정리해줘")도 같은 스킬로 처리한다. 단순 질문·조회·설명은 직접 응답해도 된다.

**변경 이력:**

| 날짜 | 변경 내용 | 대상 | 사유 |
|------|----------|------|------|
| 2026-07-29 | 초기 구성 (에이전트 4 · 스킬 5). `plan → work → review → compound` 4단계. **spec 단계 없음** — 설계 결정(현행 특정·버린 안·에러 처리 표·트레이드오프·범위 밖)을 계획 문서 앞부분에 인라인하고 게이트를 계획 승인 1개로 통합. **review는 경량 단일 패스** — 리뷰어 1명이 정확성·계약·테스트품질을 한 번에 보고, 실행 기반 증명(임시 테스트·뮤테이션)과 재검증 사이클을 생략 | 전체 | 사용자 요청: spec 없이 바로 plan, review는 오래 걸리므로 간소화 |
