# frontend 여행 계획 AI 웹 설계 (v1 — UI/UX 프론트)

- 날짜: 2026-07-24
- 위치: `frontend/`
- 상태: 승인됨

## 목적

travel-builder의 여행 계획 AI를 위한 웹 프론트엔드를 만든다. `core`는 한국관광공사 TourAPI 실데이터 + TEI 임베딩 + Qdrant 벡터검색 + Gemini 생성으로 이뤄진 RAG 기반 여행 일정 생성 엔진이지만, 아직 프론트가 호출할 HTTP API가 없다(CLI + 클라이언트 라이브러리 단계).

따라서 이번 v1은 **UI/UX 프론트에 집중한 목업 데이터 기반 웹**이다. 여행 계획 AI의 화면과 흐름을 완성도 높게 구현하고, 나중에 core API가 생기면 **데이터 레이어만 교체**할 수 있게 설계한다.

브랜드명은 임시로 **여로(Yeoro)** — "여행길" — 로 두고, 상수 하나로 관리해 나중에 쉽게 바꾼다.

## 결정 사항

| 항목 | 선택 |
|------|------|
| 작업 범위 | UI/UX 프론트 먼저 (목업 데이터). API 생기면 데이터 레이어만 교체 |
| 핵심 인터랙션 | 채팅 + 여행계획 패널 (하이브리드) |
| 디자인 무드 | 모던 · 미니멀 (깨끗한 여백), 라이트 모드 우선 |
| 포인트 컬러 | 틸·틸그린 계열 (여행 + 미니멀) |
| 화면 범위 | 랜딩 + 플래너(채팅·일정) |
| UI 라이브러리 | 외부 라이브러리 없이 Tailwind 4로 직접 경량 프리미티브 작성 |
| 지도 | 외부 지도 API 없이 미니멀 목업 지도(핀 번호)로 처리 |
| "AI 응답" | 실제 LLM 호출 아님. 미리 정의된 시나리오 기반 목업 |
| 기술 스택 | Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 (기 스캐폴딩) |

## 라우트 / 정보 구조

- `/` — 랜딩 (서비스 소개 + CTA)
- `/plan` — 플래너 (채팅 + 일정 패널, 핵심 화면)

## 화면 설계

### 랜딩 페이지 (`/`)

- **Hero**: 헤드라인("대화만으로 완성되는 여행 일정") + 서브카피 + CTA 버튼(여행 계획 시작 → `/plan`). 은은한 그라데이션 배경, 미니멀.
- **작동 방식 3단계**: ① 대화로 취향 알려주기 → ② AI가 한국관광공사 실데이터로 일정 생성 → ③ 지도·타임라인으로 확인/수정
- **특징 3가지**: 공공 관광 실데이터 기반 · AI 맞춤 추천 · 지도 중심 동선
- 심플 푸터

### 플래너 화면 (`/plan`) — 핵심

- **데스크탑 2-패널**: 좌측 채팅(40%) / 우측 일정(60%)
- **채팅 패널**: AI·유저 말풍선, 빠른 제안 칩("제주 2박3일", "맛집 위주로", "가족여행"), 하단 입력창
- **일정 패널**:
  - 상단 **여행 요약 카드** (목적지 · 기간 · 인원)
  - Day별 세로 **타임라인** + 각 일정은 **장소 카드**(사진, 이름, 카테고리 뱃지[관광지/음식점/숙박], 시간, 한 줄 설명, 지도핀 번호)
  - **지도 자리**: 미니멀 목업 지도(핀 번호 표시)
- **모바일**: 채팅 ↔ 일정 탭 전환

## 데이터 레이어 (교체 가능성)

```
frontend/src/lib/
├── api/          # getItinerary(), sendMessage() 등 async 인터페이스
└── mock/         # 한국 여행 목업 데이터(서울·부산·제주 등) + "AI 응답" 시나리오
```

- v1은 `api/`가 `mock/` 데이터를 반환한다.
- 유저가 메시지를 보내면 미리 정의된 시나리오 기반으로 일정이 갱신되는 "AI 흉내"(실제 LLM 호출 아님).
- 나중에 core API가 생기면 `api/` 내부만 `fetch`로 교체하고 화면 코드는 그대로 둔다.
- 타입은 core 도메인을 반영: `Place`(관광지/음식점/숙박), `ItineraryDay`, `ChatMessage` 등.

## 컴포넌트 구조

```
frontend/src/components/
├── ui/           # Button, Card, Badge 등 경량 프리미티브 (Tailwind 직접 작성)
├── landing/      # Hero, HowItWorks, Features, Footer
└── planner/      # ChatPanel, MessageBubble, SuggestionChips,
                  # ItineraryPanel, DayTimeline, PlaceCard,
                  # MapPlaceholder, TripSummary
```

## 상태 / 데이터 흐름

- 플래너는 클라이언트 컴포넌트. 로컬 상태(`useState`/`useReducer`)로 채팅 메시지 + 현재 일정 보관.
- 유저 메시지 전송 → `api/sendMessage()`(목업) → 시나리오 기반 일정 업데이트.
- 데이터 접근은 async 함수 뒤에 둬서 나중에 `fetch`로 교체 가능하게 유지.
